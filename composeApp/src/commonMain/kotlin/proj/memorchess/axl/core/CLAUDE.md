# Core layer (`core/`)

Platform-agnostic logic for the board, the opening graph, and spaced repetition. Persistence sits behind an interface; there is no remote backend and no synchronization layer.

- **`engine/`** — chess engine wrapper around the `chess-core` library (`io.github.alluhemanth:chess-core`). `GameEngine` is the central class: it owns board state, validates moves (SAN and coordinate-based), handles promotions, and produces position FENs. Two value classes matter: `Fen` (the full 6-part FEN string) and `PositionKey` (a FEN cropped of its move counters — the graph key). Helper types: `Player`, `ChessPiece`, `PieceKind`, `BoardLocation`, `TileColor`.
- **`graph/`** — the opening tree, keyed by `PositionKey`. `OpeningTree` is a pure in-memory graph of immutable `Node` and `Edge` values. **`TreeStore` is the single mutation chokepoint**: it wraps `DatabaseQueryManager`, owns the cached `OpeningTree`, and is what UI, interactions, and scheduling code talk to — never mutate the graph anywhere else. `TrainingScheduler` drives spaced repetition through `TreeStore` and `SchedulingAlgorithm`. `NavigationHistory` handles back/forward navigation over `PositionKey` and `Edge` values, `TrainingEntry` is a lightweight reference to a trainable position, and `NodeState` is the position-state enum. `DeleteMode` (`HARD`/`SOFT`) selects deletion semantics; the app defaults to `HARD` because storage is local only. `PreviousAndNextMoves` exists at the persistence seam only, as a DTO for `DatabaseQueryManager`.
- **`interactions/`** — game interaction controllers. The abstract `InteractionsManager` handles tile selection, move execution, and the promotion flow; `LinesExplorer` (free exploration, talks to `TreeStore`) and `SingleMoveTrainer` (spaced-repetition training, talks to `TrainingScheduler`) implement it.
- **`data/`** — the low-level persistence seam. `DatabaseQueryManager` is implemented by a Room-backed store in `nonJsMain` and an IndexedDB-backed one in `wasmJsMain` (`IndexedDbInstance`). Only `TreeStore` and those platform impls may touch this interface.
- **`scheduling/`** — `SchedulingAlgorithm` is the algorithm interface; `Fsrs6SchedulingAlgorithm` is the active FSRS 6 implementation. `CardState` holds per-card state (`dueDate`, `lastReview`, `firstReview`, `stability`, `difficulty`, `reps`, `lapses`) and `ReviewGrade` is the cross-algorithm rating enum (`AGAIN`, `HARD`, `GOOD`, `EASY`).
- **`config/`** — `ConfigItem` is the typed persisted-setting abstraction (with `DurationBasedConfigItem` and `EnumBasedAppConfigItem` specializations). The concrete settings are top-level `val`s in `StandardAppConfig.kt` (user-facing) and `InternalAppConfig.kt` (not exposed in Settings); `ALL_SETTINGS_ITEMS` backs the reset flow.
- **`auth/`** — Lichess OAuth over PKCE: `LichessOAuthClient`, `LichessSignInController`, `OAuthTokenStore`, `PkceGenerator`, and the platform-provided `OAuthLauncher`.
- **`pgn/`** — PGN import pipeline: `PgnParser` → `PgnGame` → `PgnImporter`, with `PgnImportPreview` and `PgnImportSummary` for the UI and typed `PgnParseException`/`PgnImportException` failures.
- **`date/`** — `DateUtil`, the date helpers shared across the codebase.
- **`util/`** — small shared helpers (`CanDisplayName`, `Reloader`).
