# Core layer (`core/`)

Platform agnostic logic for the board, the opening graph, and spaced repetition. Persistence sits behind an interface. There is no synchronization layer and no backend of our own, but three read only HTTP clients do reach outward: the Lichess opening explorer, Lichess study import, and the repertoire catalog served as static files from the `repertoire-data` branch on raw GitHub.

- **`engine/`** — chess engine wrapper around the `chess-core` library (`io.github.alluhemanth:chess-core`). `GameEngine` is the central class: it owns board state, validates moves (SAN and coordinate-based), handles promotions, and produces position FENs. Two value classes matter: `Fen` (the full 6-part FEN string) and `PositionKey` (a FEN cropped of its move counters — the graph key). Helper types: `Player`, `ChessPiece`, `PieceKind`, `BoardLocation`, `TileColor`. Everything in this package except `evaluation/` now lives in the `:shared` module under the same package name, so the server can use it too. `evaluation/` stays here because it is the only user of `stockfish-multiplatform`.
- **`graph/`** — the opening tree, keyed by `PositionKey`. `OpeningTree` is a pure in-memory graph of immutable `Node` and `Edge` values. **`TreeStore` is the single mutation chokepoint**: it wraps `DatabaseQueryManager`, owns the cached `OpeningTree`, and is what UI, interactions, and scheduling code talk to — never mutate the graph anywhere else. `TrainingScheduler` drives spaced repetition through `TreeStore` and `SchedulingAlgorithm`. `NavigationHistory` handles back/forward navigation over `PositionKey` and `Edge` values, `TrainingEntry` is a lightweight reference to a trainable position, and `NodeState` is the position-state enum. `DeleteMode` (`HARD`/`SOFT`) selects deletion semantics; the app defaults to `HARD` because storage is local only. `PreviousAndNextMoves` exists at the persistence seam only, as a DTO for `DatabaseQueryManager`, and `MoveInsertion` (declared in `TreeStore.kt`) is the batch insert argument. `Edge` is the immutable edge value. `GraphSerializer` reads and writes a graph as deterministic tab separated text.
- **`interactions/`** — game interaction controllers. The abstract `InteractionsManager` handles tile selection, move execution, and the promotion flow; `LinesExplorer` (free exploration, talks to `TreeStore`), `SingleMoveTrainer` (spaced repetition training, talks to `TrainingScheduler`) and `RepertoireExplorer` (read only navigation of one downloaded repertoire over a throwaway `TreeStore`, rejecting off book moves) implement it.
- **`data/`** — the low level persistence seam. `DatabaseQueryManager` is implemented by a Room backed store in `nonJsMain`, an IndexedDB backed one in `wasmJsMain` (`IndexedDbInstance`), and `InMemoryDatabaseQueryManager` for tests and transient graphs. Only `TreeStore` and those implementations may touch this interface. `DataNode` and `DataMove` are the row DTOs, `PositionKey` the cropped FEN key, `NodesPage` the bounded paging result, `SchedulingCounts` the daily tallies, and `BoundedDescendants` the capped breadth first descendant count shared by every backend so the convergence rule cannot drift. `LocalDatabase` is the platform provided accessor. `PositionKey` lives in the `:shared` module under the same package name.
- **`data/explorer/`** — the Lichess opening explorer panel. `LichessExplorerClient` calls the API, `LichessExplorerResponse` decodes it, `ExplorerCache` persists responses keyed by `(fen, source)`, `CachedExplorer` combines the two, `ExplorerSource` selects the database queried, and `ExplorerViewModel` drives the panel.
- **`data/repertoire/`** — the downloadable repertoire catalog. `RepertoireCatalogClient` fetches `manifest.json` and the PGN files it lists, accepting `schemaVersion` 1 only. `RepertoireManifest` and `RepertoireDescriptor` are that contract, `RepertoireColor` the side taught, `CatalogResult` the typed outcome so callers never inspect Ktor exceptions, `CachedRepertoireCatalog` the stale cache fallback, `InstalledRepertoireStore` the installed id set (persisted in `INSTALLED_REPERTOIRES_SETTING`), and `RepertoireLibraryViewModel` the library page driver.
- **`data/study/`** — Lichess study import. `LichessStudyClient` downloads a public study as parsed PGN, `LichessStudyImporter` runs the end to end import into the opening graph.
- **`scheduling/`** — `SchedulingAlgorithm` is the algorithm interface; `Fsrs6SchedulingAlgorithm` is the active FSRS 6 implementation. `CardState` holds per-card state (`dueDate`, `lastReview`, `firstReview`, `stability`, `difficulty`, `reps`, `lapses`) and `ReviewGrade` is the cross-algorithm rating enum (`AGAIN`, `HARD`, `GOOD`, `EASY`).
- **`config/`** — `ConfigItem` is the typed persisted-setting abstraction (with `DurationBasedConfigItem` and `EnumBasedAppConfigItem` specializations). The concrete settings are top-level `val`s in `StandardAppConfig.kt` (user-facing) and `InternalAppConfig.kt` (not exposed in Settings); `ALL_SETTINGS_ITEMS` backs the reset flow.
- **`auth/`** — Lichess OAuth over PKCE: `LichessOAuthClient`, `LichessSignInController`, `OAuthTokenStore`, `PkceGenerator`, and the platform-provided `OAuthLauncher`.
- **`pgn/`** — PGN import pipeline: `PgnParser` → `PgnGame` → `PgnImporter`, with `PgnImportPreview` and `PgnImportSummary` for the UI and typed `PgnParseException`/`PgnImportException` failures. `PgnParser`, `PgnGame` and `PgnParseException` live in the `:shared` module under the same package name, because the server validates uploaded PGN with the same parser the client validates a download with. `PgnImporter` stays here because it writes through `TreeStore`.
- **`date/`** — `DateUtil`, the date helpers shared across the codebase.
- **`util/`** — small shared helpers (`CanDisplayName`, `Reloader`).
